# Ship plan: the Pulse site, live before November

Written 12 October 2026. The client chose the design face to face on 11 October.
This is the one plan for launch; older plans are history. Target: **live by 31
October**, 80–85% of everything working, then refinements.

## What the client agreed (verbal, 11 Oct; written summary to follow)

- Design: `/prototypes/pulse-final` (branch `preview/client-prototypes`), hero
  **Blue field**. Parts of other designs get added later, as refinements.
- Theme: Pulse only. Light at launch; dark later behind the same switch.
- Pages: home, the three exam courses, book bundles, free resources, library
  (static page: usage and pricing, no online payment), blog, success stories,
  ASSIST, contact, policies, account, admin.
- English and Assamese for every visitor: a language choice on first visit,
  remembered. Assamese gets its own type scale, not English sizes reused.
- Courses: fees and admission run on ClassPlus or offline. The site only
  collects enquiries and hands off to a call or WhatsApp.
- Books: sold **only as bundles**, 2–3 bundles, each in an Assamese set and an
  English set with separate prices. No stock counts: one available / not
  available switch per language. Show a sold count (and reviews later).
  Delivery by courier or pickup at the centre; flat shipping charge; up to 5
  per order.
- Payment: Razorpay. ICT is GST registered.
- Promotions: the local campaigns backend (from `feat/landing-prototypes`),
  not the Kitsu-Lab package yet. Staff can manage them if the owner grants it.
  The top bar is sticky with the header.
- Admin: owner plus 1–2 staff, on phones and desktops equally.
- Sign-in codes over WhatsApp (Meta Cloud API). Domain: ICT owns it. Hosting:
  decided before 26 Oct.

## Schema v2

There is no production data yet, so the schema is redesigned now rather than
migrated later. Dev data is reseeded.

What is wrong with v1:

- `persons` mixes identity, the sales pipeline, consent, onboarding and the
  WhatsApp window in one row.
- `activities` is one table for lead notes and system audit, with a dozen
  optional fields that only some kinds use.
- `books` carry a price and a single language, but ICT sells bilingual bundles.
- Each enquiry is not its own record, so "how many enquiries from Facebook this
  month" cannot be answered.
- Images are bare storage ids with no size, so pages cannot reserve space or
  show a placeholder.
- No Razorpay payment record, no receipt numbering, no site settings, no
  promotions table on this line, permissions are role-only.
- Rate limiting is hand-rolled (the Convex guidelines say use the component).

Tables in v2:

| Area      | Table            | Holds                                                                                                                           |
| --------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| People    | `persons`        | phone, name, email, role, `permissions[]` (staff only), `locale`, onboarding answers, consent, verified, deleted                |
| Sales     | `leads`          | one per person: status, assignee, next follow-up, exam interest, first source, last enquiry, search text                        |
|           | `enquiries`      | every submission: lead, exam, timing, message, page, UTM source/medium/campaign, referrer                                       |
|           | `leadActivities` | notes, calls, status and follow-up changes, assignments, WhatsApp handoffs, resource opens, orders                              |
| Audit     | `auditLog`       | actor, action, entity table + id, summary: role/permission changes, exports, publishes, order status, deletions                 |
| Content   | `courses`        | exam, mode (online/offline), fee, struck fee, batch start, schedule, ClassPlus link, order, published                           |
|           | `books`          | exam, slug, per-language title, edition, pages, cover, sample pages                                                             |
|           | `bundles`        | slug, exam, localised title and description, book ids, cover, per-language price + availability, `soldCount`, status            |
|           | `resources`      | slug, exam, kind, folder, language, page images (capped), published                                                             |
|           | `posts`          | slug, locale, title, excerpt, body, cover, SEO title and description, published                                                 |
|           | `images`         | storage id, width, height, alt, tiny blur placeholder, bytes, uploaded by                                                       |
| Commerce  | `carts`          | person, lines of bundle + language + quantity                                                                                   |
|           | `orders`         | reference, person, status, fulfilment, frozen lines (bundle, language, titles, price), totals, address, courier, receipt number |
|           | `payments`       | Razorpay order and payment ids, amount, status, signature check, webhook event ids (each processed once)                        |
| Marketing | `promotions`     | kind (bar, pop-up, reel, banner), status, copy, link, image, videos, pages, schedule, priority, rest days                       |
| Settings  | `siteSettings`   | one row: shipping charge, pickup address, contact numbers, GSTIN, receipt prefix                                                |
| Auth      | `otpSendLeases`  | unchanged                                                                                                                       |
|           | rate limits      | `@convex-dev/rate-limiter` component replaces `rateLimits`                                                                      |

Rules kept from v1: integer paise, `revision` on every editable record,
tombstoned persons, page images instead of PDFs (ADR-0003), server-side pricing.

Not merged: `codex/bundle-campaign-foundation` (draft/published snapshots,
vendored Kitsu promotions, R2 media). Too heavy for the deadline and against the
"local promotions first" decision. Its cart sync and lost-response order
recovery (`lib/cart-session.ts`, `lib/cart-model.ts`) are worth reusing.

## Design system

- Tokens, fonts and motion rules from `app/prototypes/pulse-final/_theme.ts`
  move into `app/globals.css` as shadcn CSS variables, so `components/ui` take
  the Pulse look without forking.
- Sections become composable, prop-driven blocks in `components/marketing/`
  (shadcn style: small parts, `className` passthrough, `data-slot`), with no
  ICT copy inside the blocks.
- Remove: the five-palette switch, `components/dev/theme-preview.tsx`,
  `/redesign`, the prototype-only hero picker and design switcher.
- Images: `next/image` everywhere with known sizes and blur placeholders; source
  photos at least 2400 px on the long edge, exported to AVIF/WebP by Next.

## WhatsApp sign-in codes

Meta Cloud API, called from `lib/otp-transport.ts`, about ₹0.115 per code in
India. ICT's current number (+91 86380 61175) runs on the WhatsApp Business app.
Two ways to use it:

1. **Separate number (recommended).** A new SIM, registered on the Cloud API
   under ICT's Meta business portfolio. Codes come from that number; the
   current number stays exactly as it is for staff chats. Any quality problem
   with code messages cannot affect ICT's main number.
2. **Coexistence** on the current number: app and API share it. It is set up
   through Meta's Embedded Signup, which usually needs a Meta partner (a BSP),
   and it ties ICT's main chat number to the website's code traffic.

Either way ICT needs a Meta business portfolio (business.facebook.com),
business verification with GST documents, and an approved authentication
template. Before verification completes, Meta caps how many people the
number can message per day; enough for testing.
